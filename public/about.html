跨境客户经营 CRM

可信数据、受控 Agent 与评测回归

面向跨境电商与出海 B2B 的客户经营场景：先把客户和商机事实保存下来，再让 Agent 在授权范围内分析、建议和起草跟进，对客动作始终保留人工确认。

本页介绍完整产品的设计要点。演示站按真实结构搭建，使用虚构数据，纯静态运行，不会调用真实模型，也不会对外发送消息。

要解决什么问题

销售日常要在多端之间反复核对信息：WhatsApp 上的客户私域沟通、CRM 里的商机线索，以及企业内部的产品与报价政策。意向分析容易散落，客户偏好容易被忘掉，产品依据可能过时；如果让大模型直接对客，还可能出现越权承诺和幻觉折扣。

系统的做法是：销售选定客户范围后，由 Agent 读取已经确认的记忆与产品依据，协作分析商机，并产出带来源、缺失材料和下一步建议的报告。负责人可以补充方向并接续任务；对客动作必须经过独立确认。执行轨迹和分层评测用来定位事实遗漏、协作冲突和输出失败，为后续修正资料、工具或流程提供依据。

系统设计架构全景

将业务交互、受控 Agent Harness、三源分离的可信数据面与评测回归明确划界：记忆与知识摘要仅作参考，数据库始终保持唯一事实真源，对客与高敏操作必须过提案人审。

持久化 Run 与动作提案状态机

模型单回合结束只是中间态。异步队列、租约校验、6 字段带快照可逆写、人审挂起续跑与写回不确定停机共同保证长任务可控收敛。

核心能力

领域数据与权限隔离

把 CRM 核心能力封装为统一的工具契约，入参强类型校验，并在入口绑定组织租户与角色权限。Agent 只能使用已发布白名单中的工具，跨客户查询也遵守行级隔离和操作审计。

客户画像记忆

订单、合同和组织事实保存在数据库中作为真源；客户画像、价格敏感度、采购偏好和沟通禁忌由长期记忆系统提炼。日常对话增量写入，夜间再清洗去重；响应前召回高权重记忆，临时促销会衰减，核心身份偏好则持久锁定。

知识引用可追溯

企业产品与报价政策通过检索层读取，并校验知识库白名单与授权范围。引用会记录内容指纹和文档版本，复用时再次核验；已下架或失效的依据会被屏蔽，避免用过时政策给出未授权折扣。

长任务受控执行

商机深度分析往往跨多轮、耗时长。系统用显式状态机把每回合拆成意图识别、工具校验、结果观测和副作用提议，任务队列负责续跑。模型回合结束只是中间步骤，满足业务验收条件后才会进入终态。

交叉事实核验

对购买意向、交付可行性和商务政策合规性做并行只读分析，再交叉比对证据版本与字段事实。一旦发现报价与现行策略冲突、或证据不足，就挂起自动推导，生成差异报告交由人工裁决，避免幻觉继续扩散。

评测与持续改进

用规则校验加上语义评审，覆盖查询准确性、工具调用、审批合规、引用溯源和冲突识别。真实失败案例会沉淀为回归集。改进链路只允许调整工具说明、专家分工、上下文装配和记忆召回，权限隔离与外发审批规则保持锁定，补丁经回归和人工批准后再发布。

人机协同与安全边界

  • 对客动作先提案、后确认 Agent 的写入和对客沟通只会生成提案，必须在工作台经销售或主管确认后才落地，避免擅自改商机阶段或直接发信。
  • 白名单写入与一键撤销 Agent 仅可自动修改 6 个低敏感辅助字段，写入前保存快照。人工撤销时会比对是否已被销售改过，避免覆盖最新的人工修改。
  • 策略版本与紧急熔断 主管调整跟进策略时会生成新版本，并终止旧草稿的继续执行。必要时可按全租户或单个客户立即阻断尚未发出的对客动作。
  • 审批防重与并发保护 批准、拒绝和暂停在重试时复用同一请求键，避免网络抖动导致重复执行；长耗时写入还会校验队列租约，拦截超时旧进程的迟到写回。

界面与工程

  • 流式执行时间线 工作台按事件顺序展示思考、工具调用和回执。页面刷新、断网重连或任务结束后再打开，都能完整回放执行过程。
  • 移动端与多端一致 界面会适配软键盘和横幅高度，并处理中文输入法组合态，减少误触。商机看板用版本校验防止多端同时改写时的脏更新。
  • 统一领域服务与异步执行 产品界面与 Agent 运行时共享同一套领域能力，数据层按组织做行级隔离。长任务先落库再入队，由独立 Worker 执行，避免页面超时悬挂。
